2.1 引脚编码：一个 uint32 表示一个引脚

// hal_gpio.h:7-9  核心就这三行宏
#define HAL_GPIO_PIN(port, pin)    (((port) << 16) | (pin))
#define HAL_GPIO_PORT(pin_enc)     ((pin_enc) >> 16)
#define HAL_GPIO_PIN_NUM(pin_enc)  ((pin_enc) & 0xFFFF)

高 16 位存端口号（0=A, 1=B, 2=C…），低 16 位存引脚号。所以：

写法含义
HAL_GPIO_PIN(1, 12)PB12 → 十六进制 0x0001_000C
HAL_GPIO_PIN(0, 15)PA15
HAL_GPIO_PIN(4, 14)PE14（摇杆按键）

3麦克风采集与吹气检测（mic_hum.c）

Phone/mic_hum.c · 689 行 —— 全项目最核心 Phone/mic_hum.h · 53 行

这个文件负责整条链路的前半段：从两根 I2S 线上把音频捞出来 → 算出能量 → 判定是短吹/中吹/长吹/组合 → 吐出命令码。

3.1 关键前提：一个 I2S 帧 = 4 个 HalfWord

INMP441 输出 24 bit PCM，打包在 32 bit 声道槽里；V307 的 DATAR 寄存器物理宽度只有 16 bit，DMA 必须按 HalfWord 搬。于是：

// mic_hum.c:14-19
#define FRAME_CNT    128          // 一次处理 128 帧 = 128/16000 = 8ms
#define HW_PER_FRAME 4            // L高16 + L低16 + R高16 + R低16
#define HW_CNT       (FRAME_CNT * HW_PER_FRAME)   // 512 个 HalfWord

static uint16_t dma_buf_a[HW_CNT * 2];   // 1024 HW = 双缓冲
static uint16_t dma_buf_b[HW_CNT * 2];

内存里每一帧占 4 个 uint16：

帧0                帧1                帧2
[H0][H1][H2][H3] | [H0][H1][H2][H3] | ...
 ↑   ↑   ↑   ↑
 4 个候选位置 p=0,1,2,3
有效数据在哪个位置是不固定的 INMP441 只有一个声道有数据，另一个是静音；再加上 WS/CK 相位对齐上电不固定 —— 所以不能硬编码去取 H0。 这就是 Auto_Detect_Pos 存在的原因（见 3.3）。

配成 Circular + BufferSize=1024 后，硬件会在搬到一半和搬完时各产生一次中断：

dma_buf_a[0] ..... [511] | [512] ..... [1023]
   ← HT 中断处理前半区 → | ← TC 中断处理后半区 →
                        ↑ DMA 自动回绕继续写
// mic_hum.c:150-160  中断处理
void DMA1_Channel4_IRQHandler(void) {         // 麦克风 A
    if (DMA_GetITStatus(DMA1_IT_HT4)) {
        DMA_ClearITPendingBit(DMA1_IT_HT4);
        calc_energy_a(0);                     // 处理前半区
    }
    if (DMA_GetITStatus(DMA1_IT_TC4)) {
        DMA_ClearITPendingBit(DMA1_IT_TC4);
        calc_energy_a(HW_CNT);                // 处理后半区
    }
}
// DMA2_Channel1_IRQHandler 同构, 对应麦克风 B

CPU 处理前半区时 DMA 正在写后半区，两边永不撞车，也不需要阻塞等待。中断里只做一件重活：

// mic_hum.c:118-132
static void calc_energy_a(int offset) {
    int32_t mn = 32767, mx = -32768;
    uint32_t acc = 0;
    int16_t *p = (int16_t *)dma_buf_a + offset + s_valid_pos_a;  // 定位到有效 HW
    for (int i = 0; i < FRAME_CNT; i++) {
        int16_t s = *p;
        if (s < mn) mn = s;
        if (s > mx) mx = s;
        acc += (s < 0) ? (uint32_t)(-s) : (uint32_t)(s);   // 绝对值累加
        p += HW_PER_FRAME;                                 // 每帧跳 4 个 HW
    }
    s_irq_amp_a  = mx - mn;              // 峰峰值 → 判"全零"(I2S 死了没)
    s_irq_mean_a = (uint16_t)(acc / FRAME_CNT);   // 绝对均值 → 判"吹没吹"
    s_a_ready = 1;
}
为什么用两种统计量 mean（绝对均值）对持续气流敏感 → 用来判吹气；amp（峰峰值）只要不是恒定为 0 就说明 I2S 还活着 → 用来判"链路是否死掉"，因为环境噪声也有微小波动、而全零只可能是 I2S 时序漂移。

3.3 Auto_Detect_Pos：找出有效数据在哪个 HalfWord

// mic_hum.c:352-380  (A 通道, B 通道同构)
static int Auto_Detect_Pos_A(void) {
    int32_t min_amp[4] = {100000,100000,100000,100000};
    for (int g = 0; g < 10; g++) {                    // 采 10 个 DMA 周期
        while (!DMA_GetFlagStatus(I2S2_DMA_FLAG_TC)) {}
        DMA_ClearFlag(I2S2_DMA_FLAG_TC);
        for (int p = 0; p < 4; p++) {                 // 4 个候选位置各算峰峰值
            int32_t mn = 32767, mx = -32768;
            for (int i = 0; i < FRAME_CNT; i++) {
                int16_t s = (int16_t)dma_buf_a[i*4 + p];
                if (s < mn) mn = s;
                if (s > mx) mx = s;
            }
            int32_t a = mx - mn;
            if (a < min_amp[p]) min_amp[p] = a;       // 10 次取最小
        }
    }
    int32_t best_amp = 100000;
    for (int p = 0; p < 4; p++)
        if (min_amp[p] < best_amp && min_amp[p] > 5)  // 取最小且 >5
            { best_amp = min_amp[p]; valid_pos = p; }
    return valid_pos;
}
候选位置典型峰峰值判定依据
有效音频高 16bit10 ~ 100（环境噪声）✅ 最小且 > 5 → 选中
零填充位0（恒定）❌ 被 >5 排除
静音声道0（恒定）❌ 同上
低有效位 8bit0 ~ 5❌ 幅值太小被排除

检测结果存进 s_valid_pos_a / s_valid_pos_b（mic_hum.c:115-116），之后中断里就靠它偏移取数。

7.2 U 盘模式的双重死锁问题（重点理解）

现象：U 盘能被 Windows 认出来，但格式化永远失败。

根因是三件事叠在一起（更新记录一百一十二）：

  1. main.c 在 SD_Init() 之后执行了 NVIC_DisableIRQ(SDIO_IRQn)；
  2. 但 SD 卡还处在 DMA 模式：SD_WriteBlock 会死等 TransferEnd 标志；
  3. 而那个标志是 SDIO_IRQHandler 置位的 —— 中断被禁了，且 SDIO 与 USBFS 同为优先级 0 无法嵌套。

结果：写路径死等约 30 秒超时，WRITE10 失败，格式化失败。读路径却没事，因为 SD_ReadBlock 只等 DMA 硬件标志（DMA2->INTFR & 0x2000），不需要中断。

// UsbAccessoryManager.java:185-249  三个状态搞定"变长协议"
private void readLoop() {
    int parseState = 0;
    byte[] energyBuf = new byte[4];   int energyIdx  = 0;
    byte[] collectBuf = new byte[13]; int collectIdx = 0;
    while (running) {
        if (inputStream == null) { tryConnect(); Thread.sleep(500); continue; }
        int len = inputStream.read(buffer);
        for (int i = 0; i < len; i++) {
            int b = buffer[i] & 0xFF;
            if (parseState == 0) {
                if      (b == 0xFE) { parseState = 1; energyIdx  = 0; }   // 后面跟 4 字节
                else if (b == 0xFA) { parseState = 2; collectIdx = 0; }   // 后面跟 13 字节
                else                { callback.onCommandReceived(b); }    // 单字节命令
            } else if (parseState == 1) { ... 凑满 4 字节 → onEnergyReceived ... }
            else                        { ... 凑满 13 字节 → onCollectResult ... }
        }
    }
}
协议设计要点：三个包类型用"头字节"区分，且长度互不相同 0xFE + 4 字节、0xFA + 13 字节、其他单字节直接是命令。 因为命令码只用到 0x02~0x0D，永远不会与 0xFE/0xFA 冲突，所以用一个状态机就能无歧义解析。 注意 MCU 发的采集包是 14 字节含头，Android 这边只收后面 13 字节 —— 头字节已经用来切状态了。

12踩坑索引（"为什么代码长这样"）

读代码时遇到"这写得也太绕了"的地方，多半能在下表找到原因。完整版在 更新记录.txt。

编号现象根因与修法
坑 1START_ACCESSORY 成功后手机重枚举成 Mass Storage发完 START 立刻强制端口复位，打断了 AOA 切换。改为等手机自然断开
坑 2重连时非 AOA 设备被误判为 AOA*is_aoa_device=0 写在了 ENUM_RETRY 标签之前，重试时不重置。移到标签之后
坑 3软复位（开关 SOF）无效，端口卡死 30s软复位不产生总线 reset 信号。改用硬端口复位
坑 4连接成功后每 5 秒循环掉线重连keepalive 在 App 还没打开 accessory 时 TX 失败 → 误判断线 → 重连 → 再失败。删掉 keepalive，TX 失败只返错误码
坑 5USB 信号抖动被误判为断线加三级防抖：50ms → 100ms → 再查，三次都断才认
坑 8无障碍收不到目标 App 的事件accessibility_service_config.xml 里的 packageNames 白名单限制了范围。去掉该属性（装新 APK 后须关掉无障碍再重开）
坑 9点"学习"按钮立刻提示学习完成收到了本 App 自己的点击事件。排除自身包名
坑 10点播放键识别不到（最关键的坑）WebView / Compose / 自定义触摸的按钮不产生 TYPE_VIEW_CLICKED。学习模式下彻底放开事件类型与包名限制，并加 2 秒延迟
坑 11USB 被 AOA 占用，看不到 logcat改用 Toast 把事件信息打在屏幕上
一百一十USBHS Device 枚举失败，主机只发复位不发 SETUPPHY 高速握手失败降级全速后仍不通。改用 USBFS Device（PA11/PA12），全速 PHY 信号要求更低
一百一十二U 盘识别但 Windows 格式化失败SD 卡留在 DMA 模式但 SDIO 中断被禁 → 写路径死等 30s。切 SD_POLLING_MODE
一百一十三f_mount failed: 3（FR_NOT_READY）"1:" 卷号对应 pdrv=1，但 diskio.c 里 DEV_MMC=0。改回 1
一百一十五ADS1115 首读返回 0，鼠标一直飘芯片未就绪。校准前 Delay 100ms + dummy 读 + 过滤 1000~16000 外异常值；软件 I2C 不要每次重配引脚
一百零六B站巨长卡片"红框不截全也不滑动"cardTooTall && inCenter 这个为朋友圈防振荡写的条件误伤了 B站。改为分软件处理
一百零七AOA 断连后出现多个读线程 / Receiver 注册崩溃start() 加 unregisterReceiver + 线程 isAlive() 判断，做成可重入
一百零四每次连接都弹 USB 权限对话框accessory_filter.xml 的 model 还是旧板子 CH32H417，与 MCU 端 AOA_MODEL 不符。改成 CH32V307
坑 6/7学习键不自动打开目标应用 / 学习完成无反馈补 startActivity + 静态标志位 sLearningCompleted + 自动返回
