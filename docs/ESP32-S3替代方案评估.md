# ESP32-S3-WROOM-1-N16R8A 替代方案评估

> 目的: 用单颗 ESP32-S3-WROOM-1-N16R8A 替代 当前 CH32V307 + ESP8266 + HC-05 三芯片架构。
> 依据: 模组规格书 v1.3(实测功耗表) + 本项目三年踩坑记录(CH32/ESP/UART/HID)。
> 结论先行: **架构收益显著(尤其消灭 USB/UART 异构链路)，但电源要重做、实时性需实测、
> BLE 与 WiFi 共享天线失去物理冗余。推荐走"分阶段验证"路线, 不建议直接切产线。**

## 三、十大好处(按对本项目的实际收益排序)

### 1. 消灭"异构 USB/UART 链路"——直接收益最大 ★★★★★
当前最痛的问题域(2026-10 三天排查)全部位于 **CH32↔ESP8266 的 UART6/U4 模拟开关链路**
与 **App 端协议解析**: 2M 波特率 RC 低通、43% 帧损坏误判、Java CRC 符号扩展、41002 端口冲突。
ESP32-S3 **单芯片内 WiFi 协议栈 + USB HID 同 Die** —— UART 链路、波特率、
模拟开关、跨芯片时钟/电平/阻抗匹配**整条问题域直接消失**。

### 2. 原生 USB HID(device), 替代 CH32V307 的 USBFS 复合设备 ★★★★★
- tinyusb 成熟支持 HID 复合设备(鼠标+键盘+Consumer)
- **HID 报告节奏由本芯片保证**, 不再依赖"外部 MCU 按手机轮询节奏喂数据"
- 副作用: **患者手机侧的供电/枚举流程不变**(仍是 USB 供电+枚举 HID), 迁移对患者透明

### 3. BLE 替代 HC-05: 更现代、更省电 ★★★★☆
BLE 5 支持 125kbps~2Mbps、Mesh; 功耗比经典蓝牙(HC-05)低一个量级;
连接间隔可调(7.5ms~4s)——**控制通道用 BLE 保活, 平均电流可压到 10mA 级**。

### 4. 算力/内存量级提升, 为"智能手势"留出空间 ★★★★☆
双核 240MHz + 8MB PSRAM + **向量指令 + ESP-DL**:
- 压差波形可做**机器学习手势识别**(替代当前阈值+去抖状态机), 对弱吹患者更友好
- 波形可本地缓存/FFT/趋势分析, **不再依赖 App**
- 16MB Flash 可存多套参数档案/日志/OTA 双分区

### 5. SD 卡退役 ★★★☆☆
参数(NVS/SPIFFS)、日志(内置文件系统)、OTA 双分区全部内置——
去掉 SDIO 驱动/SD 卡座/8.3 短名/磨损管理一整块复杂度(本项目 SD 相关坑: fr6 短名、
日志轮转、U盘模式双主保护)。

### 6. OTA 升级 ★★★☆☆
WiFi/BLE OTA 替代"插烧录器"——**医疗设备远程维护的关键能力**(当前每次升级要
LinkE+OpenOCD)。

### 7. 单天线/单模块, BOM 与 PCB 面积下降 ★★★☆☆
CH32V307(144脚) + ESP8266 模块 + HC-05 模块 + 两颗晶振 → 单模块;
天线从 2~3 根变 1 根(省匹配/隔离设计)。

### 8. 安全能力(医疗合规加分) ★★☆☆☆
Flash 加密/安全启动/HMAC/AES——当前三芯片方案无此能力。

### 9. ADC 通道丰富(摇杆/电池/备用) ★★☆☆☆
20 路 12bit ADC 可接摇杆(替代 ADS1115 的 AIN2/AIN3)——**但精度不足, 建议仅
用于门限判断**(见第四节决策)。

### 10. 温度/功耗数据完整, 便于器件选型论证 ★☆☆☆☆
规格书功耗表可直接用于医疗设备功耗预算/热设计文档。

## 四、关键设计决策(避免踩坑)

### 4.1 双核分工——**这是实时性的生死线**
本项目已吃过中断竞争的亏(CH32 上 UART7 RXNE 与 USBFS ISR 竞争丢字节)。
ESP32-S3 用双核**物理隔离**:

| 核 | 任务 | 优先级 |
|---|---|---|
| **Core1(实时核)** | 传感器采集(ADS1115 I2C 定时) → 手势状态机 → **tinyusb HID 上报** | HID 任务最高 |
| **Core0(通信核)** | WiFi/BLE 协议栈、App 通信(参数/波形/OTA)、日志落盘 | 低于 Core1 |

- HID 上报用**固定周期任务**(如 10ms)+ 环形缓冲, 不等待网络
- 波形帧率与 HID 节奏**彻底解耦**(当前 CH32 版已用 TIM2 拆分, 逻辑可平移)

### 4.2 传感器架构: **ADS1115 保留 + 内置 ADC 只做唤醒门限**
- ESP32-S3 内置 ADC(12bit)线性度/噪声不适合 ±500Pa 精测 —— **ADS1115(16bit, I2C)保留**
- **低功耗关键**: 用内置 ADC 或外部比较器做 **"吹气超阈值"硬件/ULP 唤醒**:
  主核 light-sleep 时, ULP-RISC-V 协处理器用内置 ADC 粗采样(几十 µA 级),
  超过门限 → 唤醒主核 → 主核切 ADS1115 精测 → 手势状态机
- **新板设计建议**: 压差传感器 VOUT 同时接 ADS1115 与一路比较器(LM393)输出到
  GPIO 中断 —— 硬件唤醒最省电且无 ADC 精度顾虑
  (注意: 当前板上 ADS1115 的 ALERT 引脚不工作, 已禁用——新板用独立比较器)

### 4.3 电源重做(必做)
- 峰值 355mA(TX 100%占空比), 规格书要求**外部电源 ≥0.5A**
- 手机 USB 供电上限 500mA —— **LDO 选 1A 以上 + 470µF 以上钽/固态电容**缓冲 TX 尖峰
- 若未来电池版: 锂电池 + 低压差 LDO/SMPS, deep-sleep 8µA 才有意义(当前手机供电
  场景 deep-sleep 无意义, 收益在**发热与电流预算**)

### 4.4 低功耗策略(按场景分级)

| 场景 | 射频 | CPU | 目标电流 | 配置要点 |
|---|---|---|---|---|
| **配网/OTA/波形** | WiFi active, modem sleep DTIM=1 | 240MHz 双核 | 90~120mA | 需低延迟, `WIFI_PS_MIN_MODEM`; 波形窗口结束自动降级 |
| **正常使用(推荐默认)** | **WiFi 关, BLE 常连**(interval 50~100ms) | 80~160MHz, Core0 空闲时 `WAITI` | **15~25mA** | `esp_pm` 动态频率; 参数变更走 BLE |
| **静止(无手势/USB 挂起)** | BLE 保持(interval 可放宽) | **light-sleep**, ULP 采压差 | **0.4~1mA** | `esp_light_sleep_start()`; USB suspend 触发; 唤醒源=ULP/GPIO/USB resume |
| **无手机连接(闲置)** | 全关 | **deep-sleep** | **8µA** | RTC 定时唤醒广播 BLE(电池版才启用) |

**关键配置清单**:
1. `esp_pm_configure()`: `max_freq_mhz=240, min_freq_mhz=80, light_sleep_enable=true`
2. WiFi 节能: `esp_wifi_set_ps(WIFI_PS_MIN_MODEM)`(波形时切 `WIFI_PS_NONE`)
3. BLE: `esp_ble_gap_set_prefer_conn_params()` 调大 interval; 广播间隔 500ms~1s
4. USB: HID 空闲且 bus suspend → 进 light sleep; `CONFIG_USB_DEVICE_SUSPEND_...`
5. 外设门控: ADS1115/摇杆用 GPIO 控 MOS 供电, 仅在采样窗口上电
6. 动态频率: 无手势 80MHz; 手势识别 160MHz; 波形/OTA 240MHz

### 4.5 电源域注意
- **IO35/36/37 被 Octal PSRAM 占用** —— 引脚规划避开(33 个可用 GPIO 仍富余)
- 若用 PSRAM, **light-sleep 电流 +140µA**(可接受); 不跑 ML 时可在 menuconfig 关 PSRAM
  (但 N16R8 是封装内 PSRAM, 只能软件不启用)

## 六、风险清单(诚实版)

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| 1 | **WiFi/BLE 协议栈抖动影响 USB HID 时序**(同类问题的前车之鉴) | **高** | 双核物理隔离 + HID 固定周期任务 + 实测 HID 报告抖动(<1ms); 不达标则退 BLE 控制+USB HID 双核极端隔离 |
| 2 | **电源峰值卡线**(355mA vs 手机 500mA) | **高** | LDO 1A+470µF; 实测 TX 尖峰; 必要时限制 TX 功率(20.5→18dBm, 电流降 ~30%) |
| 3 | **BLE 与 WiFi 同天线**——原 HC-05 的**物理冗余丧失** | 中 | 医疗场景接受此取舍(HC-05 原本也少用); 若需冗余, 保留独立 BLE 模组 |
| 4 | ADC 精度不够 | 中 | ADS1115 保留(已是最优解) |
| 5 | 温度 65°C 上限(R8) | 中 | 室内设备 OK; 若热设计紧, 选 H4(-40~105°C)或降 PSRAM 使用 |
| 6 | 开发栈迁移(ESP-IDF/FreeRTOS/tinyusb) | 中 | P2 纯 C 状态机可移植; USB/NVS 重写量可控(2~3 周) |
| 7 | 单点故障(一颗 SoC 挂全挂) | 低 | WS2812 级看门狗 + 安全启动; 与三芯片"各自挂"相比风险可接受 |
| 8 | 认证/合规(WiFi/BLE 同模块, 需重新做射频认证) | 中 | 模块已带 SRRC/CE/FCC, 整机 EMC 需重测 |

## 七、结论与建议

**值得做**, 核心理由不是"省一颗芯片", 而是:
1. **消灭了本项目 80% 的历史问题域**(UART 链路/波特率/模拟开关/跨芯片帧损坏)
2. **USB HID 内建** 让"手势→鼠标"链路变成单芯片内的定时任务, 实时性可测可控
3. **BLE 让平均功耗降一个量级**(120mA → 20mA 级), 为电池版留门
4. **算力/内存为"智能手势"留出路径**(弱吹患者的核心诉求: 更宽容的识别)

**不建议**直接切产线: 先做 P0~P2(3~4 周)验证 **HID 时序 + 电源峰值**两个高风险点,
通过后再决定 P3/P4。**旧架构固件继续维护**(三芯片版是已验证的退路)。

## 八、补充确认（2026-11-04 追问）

### 8.1 蓝牙 HID —— 支持 BLE HID，不支持经典蓝牙

| 能力 | 结论 |
|---|---|
| **BLE HID（HOGP）** | ✅ 支持。ESP-IDF `esp_hid` 组件提供 HID device（键盘/鼠标/Consumer 三合一复合），BLE 5 连接 |
| **经典蓝牙 HID（BR/EDR）** | ❌ **ESP32-S3 无经典蓝牙**——HC-05 是经典 BT SPP，**必须迁 BLE GATT 自定义服务**（App 端需重写 BLE 客户端） |
| **Android/EMUI 兼容性** | ❌ **调研结论(2026-11-04): BLE HID 鼠标在华为手机上基本不可用**——AOSP 的 HID **Host** 只有经典蓝牙 profile(BluetoothHidHost)，系统设置能配的是经典 BT 鼠标/键盘；**HOGP(BLE HID host)在 AOSP 长期缺失**，纯 BLE HID 外设不会被 Android 识别为输入设备。Android 的 BluetoothHidDevice API(API 28) 是**手机当 HID 设备**的 API，不是手机收 BLE 鼠标。<br>华为官方支持列表只列经典 **HID**（使用蓝牙键盘和鼠标），无 HOGP。<br>**ESP32-S3 无经典 BT → 蓝牙 HID 路线走不通**。替代三选一：<br>①**USB HID 有线**（保底，当前方案，患者手机插线即用）<br>②**BLE GATT 自定义服务 + App 无障碍注入**（voice_config/voice_control 已有 AccessibilityService 注入能力：ESP32 经 BLE 发点击/滑动/滚动指令，App 用无障碍 API 注入系统输入——**不依赖系统 HID，华为可用**）<br>③保留经典 BT 芯片做无线 HID（不省钱，不推荐） |

### 8.2 SD 卡（SDMMC）—— 支持，且引脚可任意映射

- TRM 有 **SDHOST 控制器**（SDMMC，寄存器见 TRM p1223）；ESP-IDF `sdmmc` host + `esp_vfs_fat_sdmmc` 驱动成熟
- **关键**：SDMMC 的 CLK/CMD/D0-D3 可经 **GPIO Matrix 映射到任意可用 GPIO**——**不被 Octal PSRAM 占用的 IO35/36/37 限制**（默认引脚组 GPIO34-39 与 PSRAM 冲突，但换脚即可）
- **建议**：4-bit @ 40MHz（≈20MB/s，日志/固件/记录绰绰有余），引脚选空闲脚并在板级定义表里集中管理

### 8.4 锂电池模块设计要点（用户后续设计）

**电源路径（关键）**：
- **USB 插入 = USB 供电 + 同时充电**，无 USB = 电池供电；**不能边充边放并联**（用电源路径管理 IC）
- 推荐：**BQ24074（电源路径+充电 1A）** 或 **IP5306（充电宝方案，但静态电流 ~50µA，不适合低功耗待机）**
- 低功耗优先组合：**BQ24074 + TPS7A02 LDO（静态 1µA）+ MAX17048 电量计（3µA）**
- 3.3V 稳压二选一：**LDO（TPS7A02：静态 1µA，4.2→3.3V 效率 ~78%）** vs **buck-boost（TPS63802：效率 90%+，静态 ~11µA）**——待机优先 LDO，续航优先 buck-boost
- 电池保护：DW01A + 8205A（过充/过放/过流）

**待机电流预算**：ESP32 deep-sleep 8µA + LDO 1µA + 电量计 3µA + 保护 1µA ≈ **13µA**
**续航估算（1000mAh）**：纯待机理论数年 / light-sleep 0.4mA ≈ **100 天** /
BLE 常连 20mA ≈ **50 小时** / 日常混合（每天 4h BLE 使用）≈ **5~7 天**

**USB 供电冲突（必算）**：USB 500mA 上限内要容纳 ESP32 TX 峰值 355mA + 充电电流——
**充电限流设 300mA**，或 USB 供电时限制 WiFi TX 功率/关闭 WiFi（BLE 模式即天然规避）。

**USB-C 一口两用**：充电 + USB HID 数据（同一口，患者手机插上即充电+HID，结构对称）。
