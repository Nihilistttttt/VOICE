# VOICE 烧录与串口调试规范（固定操作手册）

> 更新: 2026-10-15 ｜ 适用: VOICE_V307 (CH32V307VCT6 + WCH-LinkE)
> 本文档为固定操作规程，工具与配置文件已固化在仓库内，按步骤照做即可。

---

## 1. 文件与工具清单

| 文件 | 用途 |
|---|---|
| `VOICE_V307/flash_v307.cfg` | OpenOCD 烧录配置（WCH-LinkE + SDI，内容与 MounRiver `bin/wch-riscv.cfg` 一致） |
| `VOICE_V307/serial_log.py` | 常驻串口监听（COM9@2M，新启动自动删旧日志，`com9_log.txt` 只保留最近一次启动） |
| `VOICE_V307/obj/TEST-INMP441-DOUBLE.hex` | 最新构建的固件（每次 make 自动更新） |
| `VOICE_V307/obj/TEST-INMP441-DOUBLE_MODE0_params.hex` | MODE=0 参数版快照（另行保存，方便回刷） |
| SD 卡 `/params.ini` | 参数配置（键值对，可拔卡手改或 U 盘模式改） |
| SD 卡 `/log.txt` (+`log.old`) | 运行日志（每次上电追加 BOOT 头，>64KB 自动轮转） |

硬件：WCH-LinkE（烧录/调试，USB）；CH340 调试串口 = **COM9** @ **2000000** 波特率（CTRL 开关切 CH340 侧）。

## 2. 构建

```powershell
# 命令行（make 路径见 build.ps1 内置）
make -C VOICE_V307/obj all
# 或 MounRiver IDE 直接构建（等价）
```
- 模式选择：`Common/Config.h` 的 `TEST_MODE`（0=手势 2=U盘 …），**改完必须重新构建+烧录**。
- 构建成功判据：exit=0、零 warning、`riscv-none-embed-size` 行出现。

---

## 3. 烧录（OpenOCD + WCH-LinkE）

```bash
openocd -f VOICE_V307/flash_v307.cfg \
  -c "program VOICE_V307/obj/TEST-INMP441-DOUBLE.hex verify; init; reset run; shutdown"
```

**成功判据**（日志尾部）：
```
** Programming Finished **
** Verify Started **
** Verified OK **
```

**已知限制（重要）**：
1. **本板未给 LinkE 接复位线**——`reset run` 命令本身不会复位芯片；**复位通过重新烧录实现**：`program ... verify` 成功（日志出现 Verified OK）后芯片自动复位重启、运行新固件，无需手动上电。
2. 强制复位备选：`mww 0xE000ED0C 0xBEEF0080`（PFIC 系统复位）——但复位后芯片可能被调试器保持 halt，需 `resume` 且不保证干净，**常规流程以重新烧录为准**。
3. SDI 调试在 USBHS host 活跃时可能不可用（H417 已证实，V307 注意）。

**常见错误**：
| 现象 | 原因/处理 |
|---|---|
| `flash driver 'xxx' not found` | 配置文件用了错误驱动名——**必须用 `bin/wch-riscv.cfg` 的写法**（驱动名 `wch_riscv`，target 类型 `wch_riscv`，expected-id 0x00001） |
| `Can't find flash_v307.cfg` | 相对路径问题——openocd/文件全用绝对路径 |
| `Error: unable to find WCH-Link` | LinkE 未接/驱动未装 |

## 4. 串口监听与日志

```bash
# 烧录前开着（或一直开着）
python VOICE_V307/serial_log.py
```
- 波特率 2000000，端口 COM9（脚本内常量，改板换口改这里）。
- **启动标记** = `SystemClk:`（main 每次上电第一行）。识别到即**删除旧日志**，`com9_log.txt` 重建为本次启动全过程。
- `com9_log.txt` 与 `VOICE_V307/com9_log.txt` 同一文件（按脚本位置落盘）。

**日志格式**：`[E/W/I/D][标签] 消息`（对齐 Android logcat 直觉）。
**运行时命令**（串口发，回车结束，终端开本地回显）：

| 命令 | 作用 |
|---|---|
| `save` | 参数表写回 SD（MODE=2 下拒绝——SD 已导出给 USB） |
| `factory` | 恢复出厂默认值并落盘 |
| `log=N` | 日志级别（0=E 1=W 2=I 3=D），默认 3 |
| `ver` | 版本/构建时间 |
| `help` | 命令表 |
| `mode0`/`mode2` | 模式切换（**预留**：待 USBFS 栈运行时化，HID/MSC 双模式共存固件后生效） |

## 5. SD 文件规范

- **参数** `/params.ini`：`key=value` 每行一条，`#` 注释，`[节]` 头仅作人读分组（固件忽略）。
  - **键名与数值范围**见 `Services/params.c` 描述符表（min/max 钳位，越界自动收回安全区间）。
  - **文件名必须是 8.3 短名**（如 `params.ini` ✓、`voice_config.ini` ✗）——FatFs `FF_USE_LFN=0`，长名报 fr=6 (FR_INVALID_NAME)。
- **日志** `/log.txt`：每次上电追加 `==== BOOT #N ====` 分段头；>64KB 自动改名为 `log.old` 重建。
- **上电流程**（MODE=0）：SD_Init → 挂载 → 读 params.ini 填参数表 → **文件缺失自动生成默认模板**（自愈）→ SD 不可用则静默用默认值，不阻塞。

### fr 错误码速查（FatFs 常用）
| fr | 含义 | 典型原因 |
|---|---|---|
| 2 | FR_NO_FILE / 相关 | 文件不存在（自愈触发点）|
| 4 | FR_NO_FILE | 文件不存在（自愈触发点，实测 2026-10-15）|
| 6 | FR_INVALID_NAME | **长文件名（LFN 未启用）**、非法字符 |
| 3 | FR_NOT_READY | SD 未就绪/初始化失败 |
| 12 | FR_NOT_ENABLED | 卷未挂载/挂载失败 |

## 6. 模式切换（当前规程）

1. 改 `Common/Config.h` → `TEST_MODE 0↔2` → 构建 → 烧录 → **重新上电**。
2. 串口 `mode0`/`mode2` 快捷切换：**接口已预留，待 USBFS 协议栈运行时化**（HID/MSC 端点与描述符需运行时可配）后生效。

## 7. 排查决策树

```
上电无日志?      → 串口 COM9/2M 是否对? CTRL 开关在 CH340 侧?
SD Init 失败?    → 卡是否插好/写保护滑块? 换卡验证
fr=6 打开失败?   → 文件名是否 8.3? (长名不支持, 改短名)
写失败读成功?    → 卡写保护? 剩余空间?
参数改了没生效?  → ①是否重新上电(仅上电读取) ②值是否被 min/max 钳位 ③log.txt 看"已从 SD 加载"行
指针偶发卡顿?    → 正常: Log_Service 限频刷 SD(~5s 一次, 数 ms)
```
