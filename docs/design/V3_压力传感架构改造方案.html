0已确认的三项决策

决策一 · 传感器角色
两个独立吸吹口
完整保留原「A/B 双麦」的双通道语义与跨通道组合。状态机结构改动最小 —— mic_t 换成 gesture_t，逻辑骨架照搬。
决策二 · 采样路径
ADS1115 为权威路径
量程由 PGA 决定，不受 VREF+ = 2.495V 限制；16 位。代价是必须先改驱动 —— 现有实现是单次转换 + Delay_Ms(10) 阻塞式，实测每通道 11.4ms。
决策三 · 手势空间
吸 / 吹 各一套手势
命令空间从 10 个扩到 18~22 个。可以直接删掉现有「音量模式」这个妥协 —— 它本来就是因为命令不够才让长吹兼职音量。

1这次换传感器的本质收益

旧架构：INMP441 → 24bit PCM → 绝对值均值(energy) → energy > 2500 → blowing 布尔量 → 5 状态机
新架构：GZP6897A → 模拟电压 → 带符号压力 P → 双阈值 zone → 双极性状态机

最重要的一点：麦克风分不清「吸」和「吹」（能量都是正的），压力传感器天生带符号。 这一条直接让命令空间翻倍，而且消掉了两个历史包袱。
对比项旧（双麦克风）新（双压力传感器）
被测量声压级（间接、受环境噪声影响）口部气压（直接、物理量）
方向信息无。吸和吹能量都是正的有符号。正=吹，负=吸
命令空间2 通道 × 4 手势 + 2 跨麦 = 102 通道 × 8 手势 + 2 跨口 = 18（可扩到 22）
音量控制需「音量模式」开关，长吹兼职长吸直接专职音量，g_volume_mode 可删
环境干扰怕风噪、怕环境声、怕遮挡密闭气路，与环境声无关
采集链路I2S + DMA 双缓冲 + 4 HalfWord 位置自动检测 + 全零看门狗单条 I2C，无位置不确定性、无时序漂移问题
阈值语义绝对能量阈值（环境中性，一次调好）零点相对偏移 |P − P0|，P0 会温漂，需运行时重校准
故障恢复有「全零检测 → I2S 重启」看门狗需新设计（I2C NAK / 读数卡死 检测）
可以整段删掉的旧复杂度 Auto_Detect_Pos（4 候选位置自动检测）、I2S_Restart（全零看门狗）、双缓冲 HT/TC 中断、HW_PER_FRAME = 4 的半字拆分逻辑、 g_volume_mode 及其在下游的所有分支 —— 这些全部是"麦克风特性"带来的附带复杂度，换传感器后一笔勾销。 mic_hum.c 的 689 行里，估计只有 mic_process 的 170 行有迁移价值。

2硬件侧的硬约束

以下全部来自 电路.txt 网表核对，是选型和时序计算的输入。

2.1 信号链（实际走线）

U5  GZP6897A  VOUT ─┬─ R26(0Ω) ──────────────── AIN1 ── ADS1115 (16bit)
                    │
                    └─ R22(0Ω) ─ LMV321B(跟随器) ─┬─ R23(22Ω) ─ ADC8 ── 片内ADC (12bit)
                                                  └─ C31(100nF) ─ AGND

U13 GZP6897A  VOUT ─┬─ R40(0Ω) ──────────────── AIN0 ── ADS1115
                    │
                    └─ R38(0Ω) ─ LMV321B(跟随器) ─┬─ R39(22Ω) ─ ADC9 ── 片内ADC
                                                  └─ C45(100nF) ─ AGND
两条路的前端是不一样的，这点很关键 ADS1115 的 AIN0/AIN1 是 0Ω 直连传感器输出，没有缓冲； 片内 ADC 走的是 跟随器 + 22Ω + 100nF（100nF 是给 SAR ADC 采样电容提供瞬时电荷的"电荷池"，不是抗混叠——22Ω 配 100nF 的转折频率有 72 kHz）。 说明设计者把片内 ADC 那条路当成主路径认真做了调理。你选了 ADS1115 为主，那么建议把两路读数做一致性比对（见第 11 章风险 1）。

2.2 参考电压与量程

项目值影响
VREF+（U16 TL431BQDBZR + R46 470Ω + R47 2kΩ）≈ 2.495 V片内 ADC 只能测 0~2.5V，正负量程会不对称
运放 LMV321B-TR 供电3V3A（轨到轨）跟随器输出可到 ~0~3.3V → 超出 VREF+，片内 ADC 会削顶
ADS1115 PGA可配 ±6.144 / 4.096 / 2.048 / 1.024 / 0.512 / 0.256 V不受 VREF+ 限制 —— 这正是选它的理由
ADS1115 供电 / 地3V3A / AGND与传感器、运放同一模拟域，好
ADS1115 I2C 上拉 R36/R372.2 kΩ 上拉到 3V3A强劲上拉，支持 400 kHz 快速模式（现在只跑 100 kHz）
ADS1115 ALERT/RDY 上拉 R355.1 kΩ → PE15可用作数据就绪中断（本方案不用，见 4.3）

2.3 通道分配（ADS1115 只有 1 个 ADC + 4 路 MUX）

MUX 通道接什么轮询权重建议
AIN0U13 压力传感器（吸吹口 2）高
AIN1U5 压力传感器（吸吹口 1）高
AIN2U17 摇杆 X（经 0Ω）中
AIN3U17 摇杆 Y（经 0Ω）中

传感器和摇杆必须共享这个 MUX —— 这是本次架构设计里最实际的约束，直接决定了采样调度器的形态。

2.4 顺带发现的两处配置过期

  • Config.h:46 注释写 OLED SSD1306 128x64，实际板上是 U12 = CH1115。引脚完全兼容（SPI 4 线：PA5/PA6/PA7/PC4/PC5），驱动基本不用改，但初始化命令集若有差异需要确认。
  • U12 的引脚命名是 SDA/SCL 而非 MOSI/SCK，容易误判成 I2C，实际是 SPI（有 CS/DC）。

4.2 非阻塞轮询调度器

/* adc_scan.h */
typedef enum { ADCCH_PRESS1 = 0, ADCCH_PRESS2, ADCCH_JOY_X, ADCCH_JOY_Y, ADCCH_NUM } adcch_t;

/* 轮询序列：压力拿 2/3 带宽，摇杆 1/3。
   等权序列 {0,1,2,3} 也可以，但压力是本次的主输入，值得加权。 */
static const uint8_t kScanSeq[] = { ADCCH_PRESS1, ADCCH_PRESS2, ADCCH_JOY_X,
                                    ADCCH_PRESS1, ADCCH_PRESS2, ADCCH_JOY_Y };

void AdcScan_Poll(void);                                  /* 主循环每轮调用一次，非阻塞 */
uint8_t AdcScan_Get(adcch_t ch, int16_t *val, uint8_t *is_new);

/* adc_scan.c 的 Poll 骨架 */
void AdcScan_Poll(void) {
    if (s_state == SCAN_WAIT_DONE) {
        if (!ADS1115_IsDone()) return;          /* ← 没完成就直接返回，不等待 */
        ADS1115_ReadRaw(&s_raw);
        s_latest[s_seq[s_idx]] = s_raw;
        s_fresh[s_seq[s_idx]] = 1;
        s_idx = (s_idx + 1) % sizeof(kScanSeq);
    }
    ADS1115_Config(kScanSeq[s_idx], kPga, kDataRate);   /* 启动下一次转换 */
    s_state = SCAN_WAIT_DONE;
}

4.3 为什么不用 ALERT/RDY 中断

ALERT/RDY 接在 PE15，理论上可以做"转换完成"事件驱动，看起来更优雅。但两个原因不建议：

  1. 软件 I2C 不能在中断里跑。一次 ReadReg 在 100 kHz 下要 540 µs 的位翻转，放进 ISR 会严重挤占 USBHS / SDIO 中断的响应。
  2. PE15 属于 EXTI15_10，已被 hal_gpio.c 无条件占用，要走它那个"无参数回调"接口，既绕又丢失上下文。

相应地，建议把 hal_gpio.c 的 EXTI 处理函数改成按需编译（或至少让 Hal_GPIO_IRQ_Config 支持 volatile 与正确的注册顺序），否则将来想用 ALERT 中断时会被堵住。

5零点校准与滤波

这是新旧架构最本质的差别：麦克风的能量阈值是"绝对值阈值"，标定一次长期有效；压力传感器的阈值是"相对零点的偏移"，而零点会随温度和时间漂移。

5.1 三级校准

时机做法为什么必须这样
开机校准上电后前 N=16 个样本取中位数作为 P0中位数抗野值（上电瞬间可能存在气路冲击、电源建立过程的扰动）
空闲重校准连续 3 s 内 |P − P0| < 漂移阈值（如 3% 满量程）→ 用 α = 0.001 的极慢 IIR 更新 P0抗温漂。MEMS 差压传感器零点温漂典型 ±0.1 %FS/°C，1 kPa 量程下约 1 Pa/°C，长时间佩戴必须补
禁用条件只要 gesture.state != GS_IDLE 就冻结 P0否则一次长吹的中间值会被当成零点，导致吹到一半"突然不灵"

5.2 数字滤波

/* 两级：中值抗脉冲 + 一阶 IIR 平滑 */
int16_t med = median3(raw_prev2, raw_prev1, raw_now);   /* 3 点中值: 去掉单点脉冲 */
p_filt = p_filt + (med - p_filt) * ALPHA / 256;          /* ALPHA≈64 对应 α≈0.25 */

α=0.25 在 68 Hz 采样下对应时间常数约 1/(2π·17Hz) ≈ 9 ms，对 100 ms 级的吸吹动作几乎无延迟，同时能把单次采样噪声压到 1/2。

5.3 双阈值迟滞（这是新增的关键设计）

/* 单阈值会让 zone 在阈值附近抖动，把一次长吹拆成「短吹+短吹」。
   旧方案用「能量阈值 + 12 tick 全零检测」回避，新方案用迟滞直接解决。 */
zone_t Press_GetZone(int16_t dp) {
    if (dp >  +TH_HIGH)  return ZONE_POS;
    if (dp <  -TH_HIGH)  return ZONE_NEG;
    if (dp >  -TH_LOW && dp <  +TH_LOW) return ZONE_IDLE;   /* TH_LOW < TH_HIGH */
    return s_last_zone;                                       /* 迟滞带内保持 */
}
参数建议初值说明
TH_HIGH待实测进入 POS/NEG 的阈值，等于原来的 g_blow_threshold 对应量。可复用现有参数 id 0
TH_LOWTH_HIGH × 0.6退出阈值。迟滞带越宽越不易抖，但会拖长"动作结束"的判定

6双极性手势状态机

6.1 核心设计：方向反转即分段

旧状态机的 5 个状态（IDLE / BLOWING / GAP / WAIT1 / WAIT2）可以完整保留，只需给结构体加一个 dir 字段表示当前段的极性，并明确一条新规则：

「吹着突然变成吸」= 当前段立即结算 + 以反方向开一个新段。
这一条规则让「吹一下再吸一下」自然产生两段，于是现有的 short_count 组合逻辑不需要任何修改就能识别「吸→吹」「吹→吸」这类异向组合。 
/* gesture.h */
typedef enum { GZ_IDLE = 0, GZ_POS, GZ_NEG } gz_zone_t;      /* press.c 输出 */
typedef enum { GS_IDLE = 0, GS_ACTIVE, GS_GAP, GS_WAIT1, GS_WAIT2 } gs_state_t;

typedef struct {                       /* 已完成的段快照 */
    int8_t   dir;                      /* +1 吹 / -1 吸 */
    uint16_t ticks;
    uint16_t gap;
    int16_t  peak;                     /* 带符号峰值 */
    int32_t  sum;
} gs_seg_t;

typedef struct {
    uint8_t  state;                    /* 沿用旧的 5 状态 */
    int8_t   dir;                      /* ← 新增：当前段极性 */
    uint16_t ticks;                    /* = 旧的 blow_ticks */
    uint16_t gap_ticks;
    uint16_t wait_ticks;
    uint16_t long_last;
    uint8_t  short_count;
    int16_t  peak;
    int32_t  sum;
    gs_seg_t s1, s2;                   /* = 旧的 s_* / s2_* */
} gesture_t;

typedef struct {                       /* ← 命令映射数据化 */
    int16_t pos_short,  pos_hold,  pos_double,  pos_triple;   /* 吹 */
    int16_t neg_short,  neg_hold,  neg_double,  neg_triple;   /* 吸 */
} gesture_map_t;

int Gesture_Process(gesture_t *g, gz_zone_t zone, int16_t dp, const gesture_map_t *map);

其余情况保持
GS_ACTIVEactive && dir_now == dirticks++，更新 peak/sum；若 ticks > MID_MAX 且距上次触发 ≥ LONG_REPEAT → 返回 map(dir).hold（连发）

if (g2.state == GS_WAIT1 && prev_g2 != GS_WAIT1 && g1.state == GS_WAIT1
    && g1.dir == +1 && g2.dir == +1) {
    cmd2 = CMD_LEFT;                       /* 口1 吹短 → 口2 吹短 */
    g1.state = g2.state = GS_IDLE;
}

「通道内异向组合」（吸→吹）已经在 6.1 的规则里天然支持，映射到第 8 章的 combo 项即可，不需要额外的时序关联代码。

7协议扩展

7.1 命令字节空间重新划分

0x00 - 0x01   保留
0x02 - 0x0D   沿用（现有 12 个命令，App 已实现）
0x0E - 0x1F   新增扩展命令（18 个）
0x20 - 0xEF   保留给未来的「带载荷命令」
0xF0 - 0xFF   包头/控制（0xFA 采集 / 0xFB 参数 / 0xFC 关能量流 / 0xFD 开能量流 / 0xFE 能量包）

为什么坚持单字节：Android 侧 MainActivity.onCommand(cmd) 是单字节分发，UsbAccessoryManager.readLoop 也靠"非 0xFE/0xFA 即命令"来解析。改成多字节会破坏这套简洁性，还得重新设计帧同步。把命令空间从 12 扩到 30，够用很久了。

7.2 能量包（0xFE + 4B）：改为有符号，格式不变

[0xFE][P1_H][P1_L][P2_H][P2_L]        P1/P2 由 uint16 改变为 int16（正=吹，负=吸）
App 必须同步改一行 UsbAccessoryManager.java:218-219 现在是 (energyBuf[0] & 0xFF) << 8 | (energyBuf[1] & 0xFF) —— 无符号拼接。 必须改成 (short)(...)，否则负值会显示成 65000+ 的大数，波形顶格。
这是唯二必须改 App 的地方之一。

7.3 采集包（0xFA + 13B）：用 judge 的 bit7 表达方向

judge = 0x01 / 0x02 / 0x03   →  吹：短 / 中 / 长
judge = 0x81 / 0x82 / 0x83   →  吸：短 / 中 / 长

好处：老 App 的 if (j1 > 0) 判断仍然成立，只是不能直接当数组下标（见下）。

App 侧有一个必改的越界点 MainActivity.java:145 定义 JUDGE_NAMES = {"", "短吹", "中吹", "长吹"}（4 个元素）， :429 直接用 JUDGE_NAMES[j1] 取值。当 j1 = 0x81 时会 ArrayIndexOutOfBounds 崩溃。
必须改为 JUDGE_NAMES[j1 & 0x7F] + 根据 (j1 & 0x80) 拼上"吸/吹"前缀。

7.4 参数协议（0xFB + id + vH + vL）：格式不变，只加 id

id含义变化
0正压阈值 TH_HIGH沿用 原「阈值」，语义从"能量"变为"正压偏移"
1短段上限 SHORT_MAX沿用
2组合等待 COMBO_WAIT沿用
3长段重复间隔 LONG_REPEAT沿用
4中段上限 MID_MAX沿用
5最小间隔 MIN_GAP沿用
6负压阈值 TH_HIGH_NEG新增 吸侧阈值（吸比吹费力，通常要单独定）
7迟滞宽度 TH_LOW新增 退出阈值
8零点漂移重校准阈值新增

8命令映射建议

8.1 生理约束决定映射原则

吹可以持续很久，吸很难持续 呼气能轻松维持 5~10 秒，吸气受肺活量限制且主观更费力。 所以：「连发/翻页」这类需要持续按住的动作应该放在吹侧，「单次/步进」类动作放在吸侧。 这条原则比"对称好看"重要得多——它直接决定患者用起来累不累。

8.2 建议映射表（第一版）

手势吸吹口 1（AIN1 / U5）吸吹口 2（AIN0 / U13）
短吹ENTER 0x02 确定BACK 0x03 返回
双短吹PLAY 0x04 播放/暂停MODE 0x0A 模式切换
长吹（连发）NEXT 0x05 下一个PREV 0x06 上一个
三短吹RETURN 0x09 返回选择SETTINGS 0x0E 新
短吸LEFT 0x0B 上翻页RIGHT 0x0C 下翻页
双短吸VOL_UP_STEP 0x0F 新VOL_DN_STEP 0x10 新
长吸VOL_UP 0x07 音量连加VOL_DN 0x08 音量连减
三短吸HOME 0x11 新CANCEL 0x12 新
跨通道组合：口1 吹短 → 口2 吹短 = LEFT；口2 吹短 → 口1 吹短 = RIGHT（与患者已习惯的 A/B 跨麦行为一致）
通道内异向组合（第二版可选）：吹→吸 = 0x13；吸→吹 = 0x14
关于音量的两点提醒 ① 长吸连发音量在生理上受限（一次吸气只能爬几格），建议同时提供「双短吸」做步进（一次 +5%），连加和步进互补。
② 原来的 g_volume_mode 可以彻底删掉 —— 音量直接由吸侧专职负责。相应地把 phone_control.c:652-655 的 VOL_MODE 出队处理、HUM_CMD_VOL_MODE 映射、以及 App 设置页里那个"音量模式"提示一并清理。命令字节 0x0D 可以回收给"切换映射表 A/B"这类用途。

8.3 用真实数据定映射，而不是拍脑袋

现有架构里已经有一整套手势采集与统计工具，可以直接复用：

  • MCU 侧：0xFA 采集模式，返回 judge / ticks / peak / avg / gap
  • App 侧：设置页的 12 项下拉 + "去极端平均"统计 + 历史列表（MainActivity.java:395-465）

只需把 COLLECT_NAMES（MainActivity.java:131-144）从"MIC_A 短吹 / 中吹 / 长吹…"改成"口1 短吹 / 长吸 / 双短吹…"。
建议第 6 阶段专门花半天，让患者按提示做一轮，用统计出的峰值/时长/间隔来定阈值和映射。这比任何理论推算都准。

9容易被忽略的节拍传染

这是一个会静默出错的连带影响 现在的主循环节拍被 Mic_Hum_Poll 里的 if (!s_a_ready || !s_b_ready) return; 门控成 8 ms（125 Hz tick）。 改用 ADS1115 后，节拍变成"由 I2C 转换完成时间决定"，如果 DR=250SPS 就是 约 4 ms。 主循环快了一倍，所有"按调用次数分频"的代码都会失准。
受影响处现在必须同步调整
phone_control.c:124 OLED 刷新分频 oled_div < 44 × 8ms = 32 ms改成 < 8（约 32 ms），否则刷新翻倍、浪费 SPI 带宽
phone_control.c:286 能量包 energy_call_count >= 33 × 8ms = 24 ms/包改成 >= 6（约 24 ms）
所有以 tick 为单位的参数
（SHORT_MAX=40t 等）		1 tick = 8 ms必须重新标定：tick 变成 4 ms 后，同一个数值代表的时间缩短一半
App 侧 t × 8 的毫秒换算MainActivity.java:330/337改成 t × 4，或让 MCU 在协议里带上 tick 周期
更稳的做法：让 tick 周期显式化 在 press.c 里维护一个基于滴答计数的 s_tick_ms，并在参数协议里新增一个 id 让 App 读取； 或者干脆把 MCU 侧所有以 tick 计的参数都换算成毫秒再比较。 无论如何，这个"1 tick 到底多少毫秒"必须只在一处定义。

12明确不做什么

不要做原因
不要保留 mic_hum 的"能量"抽象去包一层压力语义不同（能量恒正 vs 压力带符号），硬套会把"吸/吹可分"这个最大收益丢掉
不要为了兼容老 App 而保持"压力绝对值"语义同上，白丢一半命令空间
不要用 ALERT/RDY 中断去读 ADS1115软件 I2C 在 ISR 里跑 540 µs 会挤占 USBHS/SDIO；且 PE15 的 EXTI 已被 hal_gpio 占用
不要在同一次改造里顺手重写 AOA / USB 层这次改动的爆炸半径已经不小，USB 那部分刚稳定下来
不要把 ADS1115 改成"连续模式 + MUX 轮询"切 MUX 会作废当前转换，读到的是上一个通道的数据，需要延迟一拍读——引入一整个新的错位类 bug。单次转换 + 非阻塞轮询更简单可靠
不要继续往 main.c 加 TEST_MODE 分支顺手把 P7 的 hardware.c 拆出来
一句话总结这套架构 把"麦克风能量检测"整体替换为"压力手势识别"， 用 ads1115 → adc_scan → press → gesture 四层替掉单一的 mic_hum： 采样非阻塞、阈值双极性、状态机纯逻辑可单测、命令映射数据化。 顺手清掉 PB5 冲突与 I2S 遗留配置，并把最难测的那 170 行从硬件里剥出来。
本文档为设计方案，未修改任何工程文件。硬件数据全部来自 电路.txt（嘉立创 EDA 导出 JSON）的网表核对； 代码引用以当前工作区实际文件为准。凡标注"待实测"的参数均需 P1 阶段用实测数据确定。
