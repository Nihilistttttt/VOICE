## 三、剃刀判据：三个问题

对文件夹里每一样东西问这三句，**三题中任一答"是"就处理掉**：

1. **删掉它，项目还能编译、还能烧板吗？** → 能 ⇒ 它是产物
2. **它是另一个东西的副本吗？** → 是 ⇒ 删一份
3. **它属于这个项目吗？** → 不属于 ⇒ 移出去

用这三条扫一遍，结论是：**617 MB 里只有约 50 MB 需要留下。**

## 四、五类东西，五种处理

| 类 | 判据 | 处理 | 涉及 |
|---|---|---|---|
| **A 主线代码** | 你和我正在改的 | 留在仓库，git 跟踪 | `VOICE_V307/` `voice_control/` |
| **B 硬件设计** | 原理图 / PCB / 网表 | 留在仓库，收进 `hardware/` | `PUB/` `电路.txt` |
| **C 参考资料** | 别人的例程，**只读，从不编译** | **移出仓库**，物理留在本机别处 | `EXAM/` `V307_EXAM/` `CH37X_ANDROID/` |
| **D 无关项目** | 跟本项目没关系 | **移出仓库** | `doctor_merged/` `screen-projection-master/` |
| **E 产物与缓存** | 可再生的 | **删掉** + 加 ignore | `.codegraph/` `voice/` `.codeartsdoer/` 各 `build/` `obj/` |
| **F 早期副本** | 已被主线取代 | 移到 `_archive/`（仓库外） | `TEST-INMP441-DOUBLE/` `I2S_INMP441_TEST/` |

### 为什么 C 类（例程库）要移出仓库

- **它是只读的**：239 MB、10000 个文件，从来没有被编译进固件，只是查代码时翻一翻
- **占了仓库 94% 的文件数**：任何 `git status` / `git log` 都在为它买单
- **它是第三方版权内容**：WCH 的例程库，放在自己的公开仓库里并不合适
- **它随时可以再拿到**：官方例程包 / 官网，删了不心疼

> 注意：**不是删除，是移出仓库**。物理文件仍在你的硬盘上（比如 `D:/Libraries/Refs/`），
> 查代码时照样能打开。移出去的只是"git 要不要管它"。

## 六、分三批执行（按风险递增，每批可独立停下）

### T1 · 纯删除（零风险，立刻可做）

**做什么**：删掉所有可再生的产物与缓存。

```bash
cd D:/Libraries/Projects/VOICE
rm -rf .codegraph            # 189 M 代码索引，工具下次运行会重建
rm -rf voice                 # 29 M，voice_control 的完整副本（源码已验证相同）
rm -rf .codeartsdoer         # 4.2 M IDE 产物
rm -rf .preferences          # 161 K 工具配置
rm -rf VOICE_V307/obj        # 构建输出（.o/.elf/.hex）
rm -rf voice_control/app/build voice_control/.gradle voice_control/build
rm -rf voice_control/.idea
```

**效果**：617 MB → 约 390 MB。**代码零影响**（`build.ps1` / MounRiver 会重新生成 obj）。

**验证**：`build.ps1` 能重新编译通过。

**回退**：这些全是可再生的，无需回退。

> ⚠️ 执行前先确认 `.gitignore` 已经覆盖 `build/`、`.gradle/`、`.idea/`、`obj/`。

## 七、明确不做的事（边界）

| 不做 | 为什么 |
|---|---|
| **不改 MounRiver 工程名** | 工程名是 `TEST-INMP441-DOUBLE`（历史遗留），改名要动 `.cproject` / `.wvproj` / `obj/*.mk` / 链接产物名，**风险高、收益只是好看** |
| **不改 `VOICE_V307/` `voice_control/` 的目录名** | 同上，会牵动工程配置和几十处引用 |
| **不拆 `Phone/` 目录** | 上一次改成 6 个目录被否了。**真实收益不足以抵消构建配置改动风险** |
| **不引入 git submodule / LFS** | 参考资料直接移出仓库更简单；submodule 会增加日常操作复杂度 |
| **不建 CI / 不引 CMake** | MounRiver 的 makefile 够用，改造收益低 |
| **不删 `voice_control/` 里任何源码** | 只删 `build/` `.gradle/` `.idea/` 这些产物 |
| **不动 Android 工程结构** | 你说了"安卓端先不改" |
