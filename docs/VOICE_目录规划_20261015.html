一、现状问题（按架构原则逐条对照）

问题违反原则现状与影响
Phone/ 名不副实且大杂烩三层所有权19 个文件混装四类职责: 片外器件驱动（ads1115/pressure/joystick/OLED）、USB 协议栈（usbfs_device/usb_desc/usbhs_dev/aoa_host）、第三方中间件（FatFs 全家/diskio）、旧版 V2 业务（mic_hum/phone_control）+ 存储驱动（sdio_sd/sw_udisk/sdio_test）。依赖方向不可读，新人无法从目录判断"改驱动该去哪、改业务该去哪"。
Common/ 混装四类职责单一职责配置真源（Config）+ 板级 HAL（hal_gpio）+ 业务状态机（gesture_sm）+ 第三方框架（smf）同层。gesture_sm 是纯业务逻辑，与 GPIO HAL 平级放置，层次关系被抹平。
USB_Host/(SDK) 与 aoa_host/(项目) 割裂模块边界USB 主机相关代码分居两处，AOA 协议的完整视图需要跨目录拼装。
根级杂物—VOICE_V307/bl.txt、bl2.txt（散落的串口日志）、.mrs/（IDE 编码偏好文件）未忽略；ARCHITECTURE.md 内容停留在 Board/Hal/App 分层时代（已过期两轮重构）。
已合理的部分—根级六目录（固件/App/硬件/文档/单测/备份）职责清晰；hosttest 在 MounRiver 工程外（sourceEntries 约束）；_local 备份已被 git 忽略；WCH SDK 五目录保持上游原样。

按三层所有权组织项目自有代码，依赖方向只允许向下: 入口 → 业务 → 驱动/框架 → HAL/SDK。

依赖方向规则（评审新代码时照此把关）: User → Services → Drivers → Common/SDK；Framework/Middleware 被上层引用、不反向依赖；Drivers 禁止 include Services；Services 禁止直接读寄存器（经 Drivers/Common HAL）。gesture_sm 保持零硬件依赖（可宿主单测的既有成果不许退化）。

六、执行与回退

执行顺序（一次性纯移动, 不夹带任何逻辑修改）: ① git mv 全部文件 → ② 建 4 个新 obj/subdir.mk + 改 6 类构建文件 → ③ 命令行构建验证零警告 → ④ 宿主 125 断言回归 → ⑤ 用户 IDE 打开构建一次（MounRiver 重新发现源文件）→ ⑥ 真机无回归后归档。

回退方案: 全程 git mv + 单一 commit, 出问题 git revert 一次回到现布局; 移动前后 .text/.bss 应完全一致（纯移动不改代码, map 差异只允许路径变化）。

不做清单: 不改任何函数体; 不重命名任何符号; 不动 WCH SDK 目录; 不在本轮触碰 voice_control/（范围外立项）。
