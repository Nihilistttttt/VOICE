蓝牙版本 + 参数持久化 + 波形配置 方案设计（讨论稿）

2026-10-15 ｜ 状态: 设计稿, 待用户决策后实施 ｜ 复用资产: serial 底座 / FatFs / aoa_host / V2 协议 / voice_control App 骨架

一、三种运行形态总览

┌─ 日常使用(现在) ── MODE=0: 摇杆+压差 → SMF状态机 → USBFS HID → 手机
│                    零App依赖, 参数=编译期宏(本轮改为SD可调)
│
├─ 配置/调试(新增) ── 配置模式: USBHS AOA ↔ 手机配置App
│                    波形上行(压力/摇杆实时曲线) + 参数下行(写SD)
│                    ※ 手机在此模式是USB配件, 与MODE=0互斥(主机角色冲突)
│
└─ 蓝牙使用(新增) ── MODE=6(拟): 压差手势 → SMF → HC-05 SPP → 手机App
                     App经无障碍注入执行(点/拖/滚/返回) — 必须有App
                     电池供电脱离线缆的形态, HC-05板上已焊(USART3)
关键认知 1: HC-05 是 SPP 透明串口桥（不是蓝牙 HID），蓝牙版本下 MCU 无法直接变成鼠标——蓝牙版本必然依赖手机 App 做注入，复用 voice_control 已验证的无障碍能力。
关键认知 2: USBFS(MODE=0, 手机是主机) 与 USBHS AOA(配置, MCU是主机) 的主机角色互斥——配置是"进厂/调试"形态，用模式切换进入，不影响日常 HID 使用。

二、参数系统（三者共同的地基, 先做）

2.1 参数表 = 单一真源

现状: 灵敏度/阈值散在 gesture_sm.h 宏和 test_modes.c 局部变量里。新建 Services/params.c/h:

/* 参数表: 一处定义, 三处使用(SMF状态机/配置App下行/SD持久化) */
typedef struct {
    /* 摇杆 */
    int32_t  joy_deadzone;      /* 死区计数      默认 500  */
    int32_t  joy_step_div;      /* 步长分母      默认 128  */
    int32_t  joy_clamp;         /* 单帧钳位      默认 64   */
    /* 压差 */
    int32_t  press_on;          /* 按下阈值 Pa   默认 250  */
    int32_t  press_off;         /* 释放阈值 Pa   默认 150  */
    int32_t  scroll_on;         /* 滚动进入      默认 150  */
    int32_t  scroll_off;        /* 滚动退出      默认 100  */
    int32_t  long_ms;           /* 长按判定 ms   默认 500  */
    int32_t  vol_tilt;          /* 音量倾斜      默认 600  */
    /* 回主页 */
    int32_t  home_x_center;     /* 默认 540 */
    int32_t  home_y_offset;     /* 默认 24  */
    /* ...每项带 id, 对齐 0xFB 协议的 id+vH+vL */
} voice_params_t;

extern voice_params_t g_params;          /* 运行时真源 */
void     Params_Default(void);           /* 装载默认值 */
void     Params_Apply(void);             /* 下发到各状态机(替换读宏) */
uint8_t  Params_SetById(uint8_t id, uint16_t val);   /* 0xFB 下行入口 */

改造点: gesture_sm.h 的 GS_* 阈值宏 → 改读 g_params 字段（状态机已是参数化结构，改动集中在处理函数的常量引用处）；test_modes.c 的摇杆 128/64/500 同理。

2.2 SD 卡持久化（FatFs 已在工程）

项设计
文件0:/voice_config.ini — INI 风格 key=value, 人可读、可拔卡手改
上电流程SD_Init → f_mount → 读文件逐行解析 → 填 g_params → 越界值钳位到合法区间；文件缺失/解析失败/SD 不在 → 用默认值并尝试写回（自愈, 不阻塞进入模式）
保存时机显式"保存"命令触发（串口/AOA/蓝牙下行), 不自动写——防磨损、防调试期误存
校验每参数带 min/max 钳位表（结构体内), 拒绝危险值（如阈值 0 导致永触发）
SD 缺席降级MODE=0 照常运行（参数=默认值）; SD 是可选件不是依赖

三、配置模式: USBHS AOA 波形 + 参数（复用 V2 协议）

V2 时代已验证的协议直接复用, 不发明新协议:

方向帧用途
MCU→手机0xFE + 4B 能量包 / 扩展波形包波形监测: 压力 s1/s2 原始值 + 摇杆 X/Y（建议 ~100Hz, 时分进现有 0xFA 采集包结构或定义 0xFB 波形包）
手机→MCU0xFB + id + vH + vL参数下行（Params_SetById 直通参数表）
手机→MCU0xF9(拟) + key保存到 SD / 恢复默认 / 进入退出配置模式

MCU 侧: 新增配置模式函数（复用 aoa_host 连接管理 + 收发循环, V2 的 phone_control 就是模板——本轮审计已把它标记为"复活时按分层重写"的范本）。USBHS 是独立控制器, 与 USBFS(HID) 互不干扰, 模式切换即角色切换。

五、蓝牙版本（MODE=6 拟）

环节方案复用
硬件HC-05 @ USART3 PD8/PD9（重映射, 网表已核实）板上既有
MCU 侧serial 底座启用（SERIAL_ENABLE=1, RX=DMA+IDLE 断帧, TX=环形缓冲+TC）; 手势判定结果（点击/拖拽/滚动/返回）编码为协议帧上行; 参数下行同 0xFBserial.c 现成, 只差接线
HC-05 配置AT 模式设名称/配对码/波特率——建议 9600→115200（波形上传需要带宽; 手势帧 9600 也够, 折中 57600）CTRL 开关切 AT 口
手机侧App 蓝牙 SPP 连接 → 收协议帧 → 无障碍注入（与现有 voice_control 的注入逻辑同源）voice_control 注入代码
SMF 复用gesture_sm 五状态机原样复用——它的输出是抽象命令（按键位/滚轮/命令）, HID 上报与蓝牙上报只是两个不同的"输出后端"本次 SMF 化的红利

七、待你决策的四个问题

① 蓝牙形态确认: 蓝牙版本=手机 App 注入（需 App 常驻 + 配对），与 USB HID 零 App 模式并存——两种用法都要，对吗？
② HC-05 波特率: 9600（现配对默认，够手势帧）/ 57600（折中）/ 115200（波形+手势余量最大，需 AT 重配）？
③ App 合一: 配置 App 与蓝牙手势 App 合并为一个双角色 App？（建议合并）
④ 参数集: 2.1 节清单是否有遗漏（比如 CLICKNAV 的节奏 25ms/30ms 要不要也开放可调）？
风险提示: ① USBHS AOA 与 USBFS HID 主机角色互斥——配置模式进出要有清晰的用户操作（物理开关或手势长按），防止日常使用误入; ② FatFs 在 MODE=0 从未链接过（此前只用于 U 盘/FatFs 测试模式），参数系统会把它首次带入正式路径——ROM 占用 +20~30KB 需评估（当前 28360/256K，充裕）; ③ SD 卡槽与 U 盘模式共用 SDIO——模式互斥关系要写清。
