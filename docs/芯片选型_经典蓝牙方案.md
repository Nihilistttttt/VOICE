# 支持经典蓝牙的主控芯片调研（对标 ESP32-S3-WROOM-1）

> 背景: BLE HID 鼠标在华为/Android 不可用（AOSP 无 HOGP host），系统级蓝牙鼠标/键盘
> 必须走**经典蓝牙 HID Device**。本报告调研"类似 ESP32-S3 但支持经典 BT"的方案。
> 结论: **"WiFi + 经典 BT + USB OTG"三全的单芯片不存在**；最优解是取舍或双芯片。

---

## 一、关键事实先摆清

### 1.1 ESP-IDF 官方支持经典 BT HID Device（重大利好）
- **API**: `esp_hidd_api.h`（Bluedroid）——`esp_bt_hid_device_register_app`（SDP 注册 HID 设备）
  / `esp_bt_hid_device_connect` / 报表发送；官方文档 `esp_hidd` 章节完整
- **官方示例**:
  - `examples/bluetooth/bluedroid/classic_bt/bt_hid_mouse_device`——**经典 BT HID 鼠标**（周期发
    报表，电脑端光标可见）
  - `examples/bluetooth/esp_hid_device`——**Classic 或 BLE 双模 HID**（编译期切换）
- **硬件前提**: 只有 **ESP32 初代**带经典 BT(BR/EDR) 射频——**ESP32-S3 无经典 BT，
  该示例在 S3 上只能跑 BLE 分支**

### 1.2 华为手机侧（已调研）
- 华为支持**经典 BT HID 鼠标/键盘**（官方协议列表 HID，示例为罗技经典 BT 鼠标）
- **不支持** BLE HID 鼠标（AOSP 无 HOGP host）
→ **经典 BT HID device = 华为可用的系统级无线输入方案** ✓

## 二、候选芯片对比

| 芯片/模组 | WiFi | 经典BT | BLE | USB OTG | 性能/内存 | 经典BT HID Device | 评价 |
|---|---|---|---|---|---|---|---|
| **ESP32 初代**(WROOM-32/WROVER) | ✅ b/g/n | ✅ **4.2 BR/EDR** | ✅ | ❌ **无 USB** | 双核 240MHz / 520KB SRAM(+WROVER 4MB PSRAM) | ✅ **官方示例直接支持** | 经典 BT HID 唯一现成方案，**缺 USB 是硬伤** |
| **ESP32-S3**(N16R8) | ✅ | ❌ | ✅ | ✅ **USB OTG** | 双核 240MHz / 16MB+8MB | ❌ 硬件不支持 | USB/性能最优，无线 HID 走 App 注入 |
| **ESP32-S2** | ✅ | ❌ | ❌(无 BT) | ✅ | 单核 240MHz | ❌ | 排除 |
| **ESP32-C3/C6/H2** | ✅ | ❌ | ✅(BLE only) | C3/C6 部分 | 单核 | ❌ | 排除 |
| **Realtek RTL8720DN/8722DM**(AmebaD) | ✅ 双频 | ❌ **BLE 5.0 only** | ✅ | 8722DM/8721DM 有 USB2.0 | 双核 KM4 200MHz+KM0 / 512KB+PSRAM | ❌ | 无经典 BT，排除 |
| **CYW43439**(Pico W) | ✅ | ⚠️ 硬件支持(BR/EDR)，**Pico SDK 只启用 BLE** | ✅ | ❌(CYW43439 无 USB) | RP2040 双核 133MHz | ⚠️ WICED/ModusToolbox 生态才启用经典 BT，HID device 需自研 | 生态复杂，排除 |

**结论**: 没有一颗"WiFi+经典BT+USB+高性能"的现成单芯片。
Espressif 的产品线是分裂的：**ESP32=经典BT但无USB；ESP32-S3=USB但无经典BT**。

## 三、三条可行架构（按推荐度）

### 方案 A（推荐）：ESP32-S3 单芯片 + App 无障碍注入（无线不走系统 HID）
- USB HID 有线（系统级）+ BLE 传指令给 App（App 用 AccessibilityService 注入）
- 优点：单芯片、性能/内存最优、USB 保底
- 缺点：无线通道依赖 App 安装（但本项目 App 是必须安装的——**无额外负担**）

### 方案 B：ESP32 初代（经典 BT HID）+ USB 协处理器（双芯片）
- ESP32 初代跑官方 `bt_hid_mouse_device` → **系统级蓝牙 HID 鼠标/键盘**（华为可用）
- USB 有线 HID 用一颗小 USB MCU（**CH552/CH32V203** 便宜；或复用 CH32V307）
- 两芯片之间用 **UART/SPI**（注意：又引入了跨芯片链路——本项目受过其苦，
  但有"经典 BT HID 官方示例"的确定性收益）
- 优点：**系统级无线 HID，不依赖 App**
- 缺点：双芯片 BOM/布线/两份固件；ESP32 初代无 USB、SRAM 小（WROVER 版缓解）

### 方案 C：ESP32 初代单芯片（纯无线，放弃 USB 有线）
- 只保留经典 BT HID + WiFi；USB 仅用于烧录/调试（串口）
- 适用：患者手机**只走无线**的场景（例如未来平板/护理站）
- 缺点：**失去 USB HID 有线主通道**——与当前产品形态不符

---

## 四、建议

1. **当前产品形态（患者手机 USB 插线 + 手势控制）**：**方案 A（ESP32-S3）**最优——
   USB 是主通道，无线只是增值；App 注入完全够用。
2. **若"系统级蓝牙 HID"是产品硬需求**（如给平板/电脑/电视做无线鼠标）：
   **方案 B**——ESP32 初代做无线 HID 桥（官方示例保底），CH552/CH32V203 做 USB HID，
   两芯片 UART 连接（**协议要设计成"单帧原子 + 超时重同步"，避免重蹈 UART 链路覆辙**）。
3. **不建议**为经典 BT 选择 CYW43439/WICED 路线（生态与资料成本过高）。
4. **验证动作**（方案 B 定稿前）：用 ESP32 开发板 + 华为手机实测
   `bt_hid_mouse_device` 示例——**确认华为手机配经典 BT HID 鼠标可用**（含点击/滚轮/
   复合键盘），这是方案 B 成立的唯一硬前提。

## 五、附：ESP32 初代关键规格（对照 ESP32-S3）

| 项 | ESP32(WROVER) | ESP32-S3(N16R8) |
|---|---|---|
| CPU | 双核 LX6 240MHz | 双核 LX7 240MHz + 向量 |
| SRAM | 520KB + **4MB PSRAM** | 512KB + **8MB PSRAM** |
| Flash | 4MB(模组) | 16MB |
| WiFi | b/g/n | b/g/n |
| BT | **4.2 BR/EDR + BLE** | BLE 5.0 only |
| USB | ❌ | ✅ OTG FS |
| 经典 BT HID | ✅ **官方示例** | ❌ |
| ADC | 12bit(差) | 12bit(差) |
| 深度睡眠 | ~10µA | ~8µA |
| 温度 | -40~85°C | R8: -40~65°C |
